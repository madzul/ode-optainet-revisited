# Revisiting ODE opt-aiNet for heterogeneous DAG scheduling

[![Open in Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/madzul/ode-optainet-revisited/blob/main/notebooks/colab_quickstart.ipynb)
[![Open in Kaggle](https://kaggle.com/static/images/open-in-kaggle.svg)](https://kaggle.com/kernels/welcome?src=https://github.com/madzul/ode-optainet-revisited/blob/main/notebooks/kaggle_quickstart.ipynb)

Code and raw data for an equal-budget re-evaluation of **ODE opt-aiNet**, the immune-network
scheduler for heterogeneous computing proposed in the author's doctoral dissertation
(Zulianto, Institut Teknologi Bandung, 2016). ODE adds three modifications to opt-aiNet:
**O**ne-time evaluation, **D**ynamic number of clones and **E**litism.

The study re-implements the dissertation's algorithm line by line, reproduces its published
schedules exactly, and compares it under an equal evaluation budget with HEFT, CPOP, PEFT, a
genetic algorithm, CLONALG and the published formulations of opt-aiNet (de Castro & Timmis 2002;
Brownlee 2011), on 51 instances with 20 runs each.

## Main findings

| | Result |
| --- | --- |
| Reproduction | Every schedule printed in the dissertation decodes to its reported makespan (11,528; 6,389; 2,763). |
| Original code | Two defects: clones receive one stale cost, and mutation swaps about half of all genes. The reported makespan differs from the true one in 56 % of runs. |
| Ablation | O, D and E each improve opt-aiNet significantly; together they cut mean RPD from 58.5 % to 21.8 %. |
| vs. published opt-aiNet | Corrected ODE beats Brownlee's version on 45 of 51 instances and de Castro & Timmis's on 30 of 51. |
| vs. CLONALG | A tuned CLONALG performs as well as corrected ODE (no significant difference). |
| vs. HEFT | Unseeded, every metaheuristic is worse than HEFT on most instances. Seeded with HEFT's mapping, GA, ODE and CLONALG are never worse than HEFT and 6–8 % better on average. |
| Speed-up claim | The reported 5–50x speed-up reproduces (5.3–11.4x) but comes from evaluating 38–587x fewer schedules. |

## Quick start

**In the browser:** use the Colab or Kaggle badge above. On Kaggle, turn on *Settings → Internet* first.

**Locally** (Python 3.10+):

```bash
git clone https://github.com/madzul/ode-optainet-revisited.git
cd ode-optainet-revisited
pip install -r requirements.txt

python src/reproduce_dissertation.py      # dissertation schedules (seconds)
python src/verify_repro.py                # bit-exact re-run of a subset (~1 min)
python src/analyze3.py                    # statistics from the archived raw data
python src/make_figures.py                # figures/*.png
```

Run every script from the repository root.

## Repository layout

| Path | Contents |
| --- | --- |
| `src/instance.py` | Unrelated-machine DAG model; the dissertation's instances (FFT-8, random-22, input_00_02) transcribed from its appendix; random, FFT and Gaussian-elimination generators |
| `src/decode.py` | numba schedule decoder (insertion and append policies), HEFT, CPOP, PEFT |
| `src/meta.py` | opt-aiNet with O/D/E switches, line-by-line port of the dissertation code (`ode_dissertation`) with switchable repairs, de Castro & Timmis and Brownlee formulations, CLONALG, GA, random search |
| `src/reproduce_dissertation.py` | Reproduces the dissertation's printed schedules |
| `src/validate_saga.py` | Cross-checks HEFT, CPOP and PEFT against the SAGA reference library (optional, `requirements-saga.txt`) |
| `src/tune*.py` | Equal-effort parameter tuning on held-out instances |
| `src/run_exp.py`, `run_exp2.py`, `run_exp3.py` | Main experiment (51 instances × 21 algorithm variants × 20 runs, 20,000 evaluations each) |
| `src/exp_bug.py`, `exp_bug_opt.py` | Replication of the dissertation's 200-generation setting and of the defects |
| `src/analyze*.py` | Friedman and Holm-corrected Wilcoxon tests, ablation, anytime curves |
| `src/verify_repro.py` | Re-runs a subset and checks it against the archived results |
| `src/plotting.py`, `make_figures.py` | Figures and Gantt charts |
| `results/` | All raw results (one JSON line per run) and summaries |
| `notebooks/` | Colab and Kaggle versions of the quickstart notebook (generated by `tools/build_notebooks.py`) |

## Reproducing everything

```bash
for s in tune tune2 tune3 tune4 tune5 tune6 run_exp run_exp2 run_exp3 exp_bug exp_bug_opt analyze analyze2 analyze3; do
  RESULTS_DIR=results_repro python src/$s.py
done
```

About 4 hours on 2 cores. Environment variables: `RESULTS_DIR` (output folder, default
`results`), `N_JOBS` (worker processes), `INSTANCES` and `RUNS` (restrict `run_exp*.py` to a
subset). Every run is seeded by (instance, algorithm, run), so results are identical across
machines; only wall-clock times differ.

Note: `results/bug.jsonl` also contains a few runs on two extra random instances (`ii` 3 and 4)
from an interrupted run; the analysis uses only `ii` 0–2.
